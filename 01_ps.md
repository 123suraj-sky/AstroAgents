Excellent. **Astronomy** is actually a very good domain for this project because we can build a system around real scientific datasets and computational tools while keeping the experiments reproducible.

I'd shape the project as:

# 🌌 AstroAgents — Multi-Agent AI Scientific Discovery System

The goal is **not** "an AI that discovers aliens." Instead:

> A multi-agent scientific research system that investigates astronomical datasets, identifies interesting objects or anomalies, performs computational analysis, challenges the findings, and produces an evidence-backed research report.

---

## 1. What the system does

A researcher gives a question such as:

> **"Find unusual objects in this astronomical dataset and investigate whether they differ significantly from normal objects."**

The system creates a research workflow:

```text
                         Research Manager
                                │
            ┌───────────────────┼───────────────────┐
            ↓                   ↓                   ↓
     Data Scientist       Astronomy Agent      Literature Agent
            │                   │                   │
        Python Tool        Analysis Tools       Search Tool
            │                   │                   │
            └───────────────────┼───────────────────┘
                                ↓
                       Hypothesis Agent
                                ↓
                         Critic Agent
                                ↓
                       Evaluation Agent
                                ↓
                         Final Report
```

# 2. The agents

### 🔭 Research Manager

The orchestrator.

It receives:

```text
Research question
```

and breaks it into tasks.

For example:

```text
Question:
"Find unusual objects."

Manager:
 ├── Analyze dataset
 ├── Search astronomical literature
 ├── Identify anomalies
 └── Validate findings
```

It then delegates those tasks to other agents.

---

### 📊 Astronomy Data Agent

Responsible for actual dataset analysis.

It can use tools such as:

```text
Python
Pandas
NumPy
SciPy
scikit-learn
```

For example:

```text
dataset
   ↓
cleaning
   ↓
feature analysis
   ↓
clustering
   ↓
anomaly detection
```

Possible algorithms:

```text
Isolation Forest
DBSCAN
K-Means
PCA
Random Forest
Statistical tests
```

---

### 🔭 Astronomy Analysis Agent

Interprets astronomical measurements.

For example:

```text
brightness
temperature
spectral features
redshift
coordinates
magnitude
```

It can reason about relationships between these measurements.

---

### 📚 Literature Agent

Searches scientific literature to determine whether a discovered pattern has already been documented.

For example:

```text
Anomaly detected
      ↓
Literature Agent
      ↓
Search scientific papers
      ↓
Find similar observations
      ↓
Compare findings
```

This is where **RAG/search + agent tool calling** becomes useful.

---

### 🧠 Hypothesis Agent

Given an interesting observation:

```text
"Object X has unusual characteristics."
```

it proposes possible explanations.

For example:

```text
Hypothesis A
Hypothesis B
Hypothesis C
```

But these are explicitly treated as **hypotheses**, not established facts.

---

### 🧐 Critic Agent

This is one of the most important agents.

Its job is to challenge the other agents.

For example:

> "The anomaly may simply be caused by missing data."

or:

> "The observed correlation isn't statistically significant."

This prevents the system from simply accepting whatever the first agent says.

Different agents get different tools.


### Literature Agent

```text
Scientific Search Tool
 ├── search_papers()
 └── retrieve_paper()
```

### Astronomy Agent

Potentially:

```text
Astronomy Data Tool
 ├── query_catalog()
 ├── lookup_object()
 └── retrieve_observations()
```

### Visualization Agent

```text
Python Tool
 ├── create_scatter_plot()
 ├── create_histogram()
 └── create_sky_map()
```

The important part:

**The LLM decides whether it needs a tool.**

For example:

```text
LLM:
"I need to determine whether these two

        ↓

Python Tool

        ↓

t-test / statistical calculation

        ↓

Result

        ↓

```

# 4. Where the multi-agent part becomes interesting

Suppose the system detects an unusual object.

You could have:

```text
Data Agent
    ↓
"Object 3817 is an anomaly."
    ↓
Astronomy Agent
    ↓
"Let's examine its properties."
    ↓
Literature Agent
    ↓
"Similar objects have been observed."
    ↓
Hypothesis Agent
    ↓
"Possible explanation: ..."
    ↓
Critic Agent
    ↓
"Evidence is insufficient."
    ↓
Data Agent
    ↓
Run additional analysis
    ↓
Final conclusion
```

Notice that this is **not a fixed linear pipeline**.

The agents can trigger additional investigation.

That's where it becomes genuinely agentic.

# 5. Agentic Evals

This is where I think the project can become much stronger than typical portfolio projects.

We'll create a **scientific evaluation framework**.

Suppose the system investigates 100 known astronomical cases.

We can measure:

### Data analysis

```text
Did the agent select appropriate analysis?
```

### Tool selection

```text
Did it choose the correct tool?
```

### Numerical correctness

```text
Are calculated values correct?
```

### Scientific reasoning

```text
Does the conclusion follow from the evidence?
```

### Evidence usage

```text
Are claims supported by observations/sources?
```

### Hypothesis quality

```text
Does the proposed hypothesis
actually explain the observation?
```

### Critic effectiveness

```text
Did the critic identify genuine weaknesses?
```

# 6. Guardrails

This project gives us a great opportunity to demonstrate **scientific guardrails**.

### Guardrail 1 — Unsupported claims

If an agent says:

> "This object is definitely a new type of star."

the system can flag:

```text
Unsupported scientific claim
```

and require evidence.

---

### Guardrail 2 — Citation verification

```text
Agent claim
     ↓
Citation verifier
     ↓
Does source support claim?
     ↓
YES → accept
NO  → reject
```

---

### Guardrail 3 — Numerical verification

If an LLM says:

```text
Mean = 48.23
```

we can independently calculate it using Python.

```text
LLM result
     ↓
Python verification
     ↓
Match?
```

This is much better than trusting an LLM's arithmetic.

---

### Guardrail 4 — Tool permissions

For example:

```text
Literature Agent
     ├── Search papers ✓
     ├── Python ✓
     └── Modify dataset ✗

Data Agent
     ├── Python ✓
     ├── Dataset ✓
     └── Web search ✗
```

Each agent gets only the tools it needs.

```text
       ↓             ↓              ↓             ↓
```

This gives us a project where **every major concept has a real purpose**:

* **Multi-Agent System** → different scientific responsibilities
* **Tool Calling** → Python, astronomy data, scientific search
* **Agentic Workflow** → agents decide what investigation to perform next
* **Guardrails** → prevent unsupported claims, unsafe tools, bad calculations
* **Agentic Evals** → evaluate complete trajectories, not just final text
* **LLM Observability** → trace every LLM/tool/agent interaction
* **Scientific Evals** → numerical and statistical verification
* **RAG/search** → scientific literature and prior findings

I think this is a **very strong direction for your second project**, especially because it is substantially different from the typical "AI chatbot + RAG" portfolio project.
